# Jobs that CI runs and `make ci-local` cannot.
#
# Format: job-id<TAB>reason. A bare job id is rejected; the reason is the point.
# Every entry here is a hole in "green locally means green in CI", so each one
# has to be worth the hole.
#
# The bar: a job belongs here only when reproducing it locally is impossible
# rather than merely inconvenient. Needing a credential, a hosted service, or a
# model is impossible. Being slow is not.

claude-review	Runs the review passes in REVIEW.md against the diff by invoking a model. Not reproducible locally: it needs credentials and produces a judgement, not a verdict. Advisory only -- ci-local is the required status check, this is not.
claude	The on-demand responder, triggered by an @claude mention on an issue or a review comment. Runs no checks and gates nothing; it exists so a human can ask for work in a thread. Nothing local corresponds to a mention.
cla	Asks whether the author of a pull request has agreed to the contribution terms. Not reproducible locally by design: the answer depends on who opened the pull request and on GitHub's own view of whether they are inside this organisation, neither of which exists on a laptop. It gates a merge and nothing else.
publish	Publishes the package to PyPI as open-meridian, run by hand. Not reproducible locally by design: it proves its identity to PyPI with GitHub's, and a local target that could publish would mean anybody could release from a laptop. The checks it runs first are `make check-vendored` and `make package`, both in ci-local.
base-image	Pushes the plugin base image to ghcr for a PyPI release, after the upload, by hand like publish. Not reproducible locally by design: it pushes with GitHub's token, and a local target that could push would mean anybody could release a base from a laptop. What it builds is `make base-image`, whose output `make check-scaffold` proves, both in ci-local.
